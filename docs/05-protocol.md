# 05 蓝牙协议

把手机 App（nRF Connect / LightBlue）当成客户端就能自己写上位机。
设备名 `DLG-CLOCK-xxxx`，广播可连接。

## 1. GATT 结构

| 项 | UUID | 属性 |
|---|---|---|
| 主服务 | `0000ff00-0000-1000-8000-00805f9b34fb` | 自定义服务 |
| 长值特征 | `0000ff01-0000-1000-8000-00805f9b34fb` | Write（Write Request，带响应） |

所有指令都写这个特征。ATT 默认 MTU 23，所以**单包有效载荷最大 20 字节**。
超过 20 字节的数据（比如网络名位图）按偏移分块发。

固件在收到数据后只更新内存里的变量，真正的绘图发生在 1Hz 定时器里，
避免在蓝牙回调里做耗时 SPI 操作。

## 2. 包类型一览

| 首字节 | 名称 | 长度 | 频率 |
|---|---|---|---|
| `0xB0` | 监控数据 | 20 | 每秒 |
| `0xB1` | 主机名 | 2+n | 连接后一次 |
| `0xB2` | 扩展数据（GPU/网络类型） | 4 | 每秒 |
| `0xB3` | 网络名位图 | 4+n | 名称变化时 |
| `0x91` | 设置时钟 | ≥8 | 一次性对时（网页 / 手机 / 脚本），**独立万年历的主要用途** |
| `0x92` | 时钟漂移校准 | 4 | 对时满 2 天后可选，见 [11 浏览器对时](11-web-timesync.md) |

> **注意**：固件先判断 `0xB0~0xB3`，最后才判断 `>= 0xA0`（OTA）。
> 自己加指令时不要把首字节放到 OTA 区间里。

## 3. `0xB0` 监控数据（20 字节）

| 字节 | 内容 |
|---|---|
| `[0]` | `0xB0` |
| `[1]` | CPU 占用 %，0~100 |
| `[2]` | 内存占用 %，0~100 |
| `[3]` | flags，bit0=在线，固定 `0x01` |
| `[4..5]` | 内存已用 MB，uint16 小端 |
| `[6..7]` | 内存总量 MB，uint16 小端 |
| `[8..11]` | 下载速度 B/s，uint32 小端 |
| `[12..15]` | 上传速度 B/s，uint32 小端 |
| `[16]` | 时 |
| `[17]` | 分 |
| `[18]` | 秒 |
| `[19]` | C 盘占用 %，0~100 |

收到这个包即视为「PC 在线」：蓝牙图标变绿，左上角显示网络名，底部显示主机名。
未连接时蓝牙图标为红色，左上角（网络名的位置）显示 **「主机未连接」**，
同时固件跑一段模拟曲线（方便单独测试屏幕）。

## 4. `0xB1` 主机名

| 字节 | 内容 |
|---|---|
| `[0]` | `0xB1` |
| `[1]` | 字符数 n（≤15，屏幕最多显示 9 个） |
| `[2..2+n-1]` | ASCII 主机名 |

例：`B1 0A "DESKTOP-01"` → 屏幕左下角、蓝牙图标右侧显示 `DESKTOP-01`（大写，`_` 变 `-`）。

## 5. `0xB2` 扩展数据（6 字节）

| 字节 | 内容 |
|---|---|
| `[0]` | `0xB2` |
| `[1]` | GPU 占用 %；`0xFF` 表示取不到（显示 `--`） |
| `[2]` | 网络类型：0=未知，1=有线，2=WiFi |
| `[3]` | 保留，填 0 |
| `[4]` | CPU 温度 ℃；`0xFF` 表示取不到 |
| `[5]` | GPU 温度 ℃；`0xFF` 表示取不到 |

温度显示在 CPU / GPU 标签右侧，格式 `62°C`；取不到时显示 `--`。

## 6. `0xB3` 网络名位图

因为固件只有 ASCII 字模，中文 SSID 由电脑端渲染成黑白位图下发。

| 字节 | 内容 |
|---|---|
| `[0]` | `0xB3` |
| `[1]` | 位图宽度（像素），当前固定 **92** |
| `[2]` | 总字节数（= `ceil(w/8) * 15`，w=92 时是 180） |
| `[3]` | 本块字节偏移 |
| `[4..]` | 数据，每包最多 16 字节 |

位图格式：

- **1bpp**，`1` = 白色像素，`0` = 黑底
- 每行 `ceil(w/8)` 字节，**从上到下**逐行
- 每字节**高位在左**（bit7 是这一行最左边的像素）

分块发送示例（180 字节 → 12 包）：

```
B3 5C B4 00 <16字节>     offset 0
B3 5C B4 10 <16字节>     offset 16
...
B3 5C B4 B0 <4字节>      offset 176  ← 收满后固件整块重绘
```

固件收到最后一块时把缓存整块贴到左栏第一行，发新的一套会覆盖旧的。

## 7. 用 Python 手动发一包

```python
import asyncio
from bleak import BleakClient

ADDR = "18:BC:5A:5A:87:81"
UUID = "0000ff01-0000-1000-8000-00805f9b34fb"

async def main():
    async with BleakClient(ADDR) as c:
        p = bytearray(20)
        p[0] = 0xB0
        p[1], p[2] = 50, 70          # CPU / RAM %
        p[3] = 1
        p[4], p[5] = 8192 & 0xFF, 8192 >> 8     # 已用 8GB
        p[6], p[7] = 16384 & 0xFF, 16384 >> 8   # 共 16GB
        p[8:12] = (2_500_000).to_bytes(4, "little")   # 下载 2.5MB/s
        p[12:16] = (300_000).to_bytes(4, "little")    # 上传 300KB/s
        p[16], p[17], p[18] = 20, 15, 33
        p[19] = 80                   # C 盘
        await c.write_gatt_char(UUID, p, response=True)

asyncio.run(main())
```

## 8. 独立万年历模式下的对时（补充）

> 本仓库固件已改为 `STANDALONE_CALENDAR=1`：上电锁定万年历卡片，
> 不显示「主机未连接」、不生成模拟监控数据，时间**永远来自本地 RTC**。
> 下面两个包是日常唯一会用到的写入。完整说明见 [11 浏览器对时](11-web-timesync.md)。

### `0x91` 设置时钟

写 `0xFF01`，最少 8 字节。网页按 HMCLOCK 原版发 12 字节，后 4 字节本固件忽略。

| 字节 | 内容 |
|---|---|
| `[0]` | `0x91` |
| `[1..2]` | 年，uint16 小端（2026 → `EA 07`） |
| `[3]` | 月，**0-based**（0=1月） |
| `[4]` | 日，1-based |
| `[5..7]` | 时 / 分 / 秒 |
| `[8..11]` | 星期 / 农历年-2020 / 农历月 / 农历日（HMCLOCK 原版字段，本固件忽略并自行重算） |

例：2026-11-19 09:30:00 → `91 EA 07 0A 13 09 1E 00`

固件 `clock_set()` 收到后：

1. 写入 `year/month/date/hour/minute/second`（内部 `date` 是 0-based，所以 `[4] - 1`）
2. `cal_sync_date()` 用内建农历表 / 节气表 / 节日表重算农历、星期、节气、节日
3. `app_clock_timer_restart()` 重新对齐 1 秒节拍
4. `rtc_save_now()` 立刻把时间快照写入 SPI Flash `0x3C000` 扇区

之后**断开蓝牙也照常走时**，断电重启从快照恢复。

### `0x92` 时钟漂移校准

| 字节 | 内容 |
|---|---|
| `[0]` | `0x92` |
| `[1..2]` | 秒差，有符号 int16 小端（正数=设备快了） |
| `[3]` | `0x00` |

固件按 `diff / cal_minute` 累积修正量，由 `clock_fixup()` 每 60 次 tick 调整一次
定时器间隔。要求 `cal_minute >= 2880`（对时满 2 天）且 `> 0`；
`cal_minute <= 0` 时固件直接跳过，避免除零 HardFault。

### `0xFF01` 回读（13 字节）

| 字节 | 内容 |
|---|---|
| `[0..1]` | 年，uint16 小端 |
| `[2]` / `[3]` | 月（0-based） / 日（1-based） |
| `[4..6]` | 时 / 分 / 秒 |
| `[7..10]` | `cal_minute`，int32 小端（`-1` = 从未对时） |
| `[11..12]` | 当前时钟修正值（int16 小端低 16 位） |

`clock_push()` 在开机 / 连接时各推送一次，**连接期间每秒再推送一次**，
保证网页 `readValue()` 拿到的是实时走时值（时间校准靠它检测分钟跳变）。
断开后停止推送，不占用内核消息队列。

> `clock_push()` 用 `KE_MSG_ALLOC_DYN(..., custs1_val_set_req, N)` 申请 `value[]`，
> `N` 必须 ≥ 13；早期版本写成 11 会越界 2 字节，已修正。

### Flash 时间快照

`0x3C000` 扇区，256 个 16 字节槽顺序追加、写满才整片擦除：

```
magic(4)="RTC1" | seq(4) | year(2) | month/day/hour/minute/second(5) | checksum(1)
```

**每分钟**（`clock_update()` 返回 `retv >= 1`，即分钟变化时）写一次，
对时后立即再写一次；重启取 seq 最大的合法记录。约 4.3 小时才擦一次扇区。
